# แบบข้อมูลสินค้าและสต๊อก — โมดูล inventory (ฉบับออกแบบใหม่ 2026-10-23)

สถานะ: **ตกลงครบทุกข้อแล้ว · ขั้น 0–4 เสร็จ (2026-10-23) · ขั้น 5 กำลังทำ (5.0–5.3 เสร็จ 2026-10-24)** — ใช้ทั้ง oas และ oms.in.th (ecommerce/pos)
ลำดับงาน: ทำระบบใหม่ให้ถูกตามแบบนี้ก่อน ตัวปรับรุ่นจากข้อมูลเดิมทำทีหลัง
ความเข้ากันได้กับ oms.in.th: ข้อ 7 · บันทึกความคืบหน้า: ข้อ 9

---

## 1. หลักการ

### 1.1 ข้อมูลสินค้าต้องตอบคำถามจริงสามข้อ

| คำถาม | ตัวอย่าง | ตอบด้วย |
|---|---|---|
| **อะไร** | เสื้อยืดคอกลม สีแดง ไซซ์ S | สินค้า + variant |
| **ขายเป็นหน่วยไหน** | ยิงบาร์โค้ดนี้ได้ไข่ 1 ฟอง หรือ 1 โหล | หน่วยขาย (บาร์โค้ด + ตัวคูณ) |
| **ชิ้นไหน** | โน้ตบุ๊กเครื่องหมายเลข F7N0CV1 | serial number |

บาร์โค้ดบนกล่อง (GTIN/EAN) ตอบได้แค่ "อะไร + กี่หน่วย" — ทุกเครื่องในรุ่นเดียวกันมีบาร์โค้ดกล่องเหมือนกัน
สิ่งที่ตอบว่า "ชิ้นไหน" คือ serial เท่านั้น

### 1.2 ข้อมูลดิบ กับ ข้อมูลแสดงผล

- **ข้อมูลดิบ** เขียนแล้วไม่แก้ เพิ่มได้อย่างเดียว : บรรทัดเอกสาร · สมุดบัญชีสต๊อก (movement) · ชั้นต้นทุน (layer — ยกเว้น `remaining_qty`) · การตัดชั้นต้นทุน (allocation)
- **ข้อมูลแสดงผล (cache)** คำนวณใหม่จากข้อมูลดิบได้ทุกเมื่อ ด้วยคำสั่ง "คำนวณใหม่" (ข้อ 5.6)
- หน้าจอแสดงผิด = ไปดูข้อมูลดิบแล้วสั่งคำนวณใหม่ ไม่ใช่แก้ตัวเลขที่ cache
- ข้อยกเว้นเดียวที่แก้ข้อมูลดิบ: บันทึกใบรับซ้ำหลังของถูกขายไปแล้ว allocation ของการขายย้ายมาชี้ชั้นใหม่ของ
  ใบรับเดียวกัน (`Fifo::receive` รับช่วง · ของเดิมจาก oms) — จำนวน ทุน และการเคลื่อนไหวของ allocation ไม่เปลี่ยน

### 1.3 กติกาการตัดสต๊อกและต้นทุน

> **รู้ตัวตน ใช้ของตัวตนนั้น · ไม่รู้ ใช้วิธีตัดที่ตั้งไว้**

- ตัวตน = serial ที่ยิง หรือเลขล็อตที่ระบุ → ตัดชิ้น/ล็อตนั้น ใช้ต้นทุนของมัน
- ไม่ระบุ → วิธีตัดของระบบ (ตอนนี้ FIFO = รับก่อนออกก่อน · อนาคต FEFO = หมดอายุก่อนออกก่อน)
- คืนของ → กลับเข้าชิ้น/ชั้นเดิมด้วยต้นทุนเดิม
- ทุกครั้งบันทึกว่า "ตัดจากชั้นไหน เท่าไร" ไว้ใน allocation เสมอ — ตรวจย้อนได้ว่าต้นทุนของการขายแต่ละครั้งมาจากไหน

## 2. โครงข้อมูลสี่ชั้น (ตามแบบ e-commerce / ERP ทั่วไป)

```
inventory_product        สินค้า (หน้าสินค้าในร้านออนไลน์)        product_code
  └─ inventory           variant = กองสต๊อก (สิ่งที่นับ ขาย รายงาน)  sku
       ├─ inventory_items   หน่วยขาย (ยิงแล้วตัดกี่หน่วย)          barcode
       │                    ชิ้น (เครื่องไหน — เฉพาะนับรายชิ้น)     serial_no
       └─ inventory_cost_layer  ล็อตที่รับเข้า (ทุน · เหลือ · หมดอายุ)  lot_no
```

- สินค้าธรรมดา = สินค้า 1 ตัว มี variant เดียวที่ไม่มีตัวเลือก (เหมือน Shopify)
- ledger · ชั้นต้นทุน · เอกสาร · POS · ecommerce อ้าง `inventory_id` อยู่แล้ว
  เมื่อ `inventory` คือ variant การอ้างอิงเหล่านี้ไม่ต้องย้าย
- ตัวเลือกสูงสุด 3 ตัว (`option1..3`) แบบเดียวกับ Shopify — นำเข้า/ส่งออก CSV
  ของร้านออนไลน์ทั่วไปได้ตรง และรายงาน "ขายดีตามสี" คือ GROUP BY ค่าตัวเลือก

### 2.1 รหัส

| รหัส | ตาราง | ความหมาย | ซ้ำ |
|---|---|---|---|
| `product_code` | inventory_product | รหัสสินค้า/รุ่น · ทำ URL ร้านออนไลน์ · จัดกลุ่ม | UNIQUE |
| `sku` | inventory | รหัส variant = สิ่งที่นับสต๊อก · ใช้ในเอกสาร/รายงาน | UNIQUE |
| `barcode` | inventory_items (หน่วยขาย) | รหัสที่ยิงเพื่อขาย · ไม่มี GTIN ระบบออกให้ | UNIQUE |
| `serial_no` | inventory_items (ชิ้น) | เครื่องไหน · ไม่ระบุตอนรับเข้า ระบบออกให้ | UNIQUE |
| `lot_no`, `expiry_date` | inventory_cost_layer | ล็อตที่รับเข้า · ว่างได้ | — |

เลิกใช้: `inventory.product_code` (ย้ายไปสินค้าแม่) · `inventory_items.sku` · `inventory_items.product_no`

**ปรับจากข้อเสนอเดิม:** บาร์โค้ดรุ่นของสินค้ารายชิ้นไม่ซ้ำไปอยู่บนทุกแถวชิ้น แต่เป็นแถว
"หน่วยขาย" หนึ่งแถวของ variant นั้น ส่วนแถวชิ้นมีแค่ `serial_no` — ผลคือ `barcode` และ
`serial_no` บังคับ UNIQUE ในฐานข้อมูลได้ทั้งคู่ และแยกชัดว่าแถวไหนตอบ "อะไร" แถวไหนตอบ "ชิ้นไหน"

## 3. ตาราง

`*` = cache (ข้อ 5.6) · ตัวเลขจำนวน/เงินใช้ DECIMAL ตาม oms.in.th เพื่อให้คำนวณใหม่ได้ค่าเดิมเป๊ะ
(double บวกกันหลายพันแถวแล้วคลาดเศษ — คำนวณใหม่จะไม่ตรงกับยอดเดิม)

### 3.1 `inventory_product` — สินค้า (ใหม่)

```
id                int unsigned PK
product_code      varchar(150) NOT NULL UNIQUE
topic             varchar(150) NOT NULL
description       text
category_id       varchar(10)            -- ตารางแกน category
count_stock       tinyint NOT NULL       -- วิธีนับ ใช้ทุก variant: 0 ไม่นับ (บริการ) · 1 นับจำนวน · 2 นับรายชิ้น
unit              varchar(50) NOT NULL   -- หน่วยฐาน = หน่วยเล็กสุดที่ขาย/นับ (ฟอง ชิ้น เครื่อง)
vat               tinyint NOT NULL       -- วิธีคิด VAT ของราคาขาย
allow_negative    tinyint NOT NULL DEFAULT 0
option1_name      varchar(50)            -- เช่น สี
option2_name      varchar(50)            -- เช่น ไซซ์
option3_name      varchar(50)
is_active         tinyint NOT NULL DEFAULT 1
published         tinyint NOT NULL DEFAULT 0   -- แสดงในร้านออนไลน์
created_at, updated_at
KEY category_id · KEY is_active
```

- `count_stock` และ `unit` **เปลี่ยนไม่ได้เมื่อมีรายการในสมุดบัญชีแล้ว** — ยอดเดิมนับด้วยกติกาเดิม/หน่วยเดิม
- รูปและรายละเอียดเพิ่มเติมอยู่ใน `inventory_meta` (ผูกกับ product)

### 3.2 `inventory` — variant = กองสต๊อก

```
id                int unsigned PK
product_id        int unsigned NOT NULL  -- inventory_product.id
sku               varchar(150) NOT NULL UNIQUE
option1           varchar(100)           -- ค่า เช่น แดง
option2           varchar(100)           -- เช่น S
option3           varchar(100)
topic*            varchar(255)           -- ชื่อเต็มสำหรับ POS/เอกสาร = product.topic + ค่าตัวเลือก
price             decimal(14,4) NOT NULL DEFAULT 0   -- ราคาขายต่อ 1 หน่วยฐาน
cost*             decimal(14,4) NOT NULL DEFAULT 0   -- ต้นทุนต่อหน่วยฐานของสิ่งที่จะถูกตัดถัดไป (แสดงผลเท่านั้น)
stock*            decimal(16,4) NOT NULL DEFAULT 0   -- คงเหลือเป็นหน่วยฐาน
is_active         tinyint NOT NULL DEFAULT 1
sort_order        int NOT NULL DEFAULT 0
created_at, updated_at
UNIQUE (product_id, option1, option2, option3)
KEY product_id
```

- ฟิลด์เฉพาะร้านออนไลน์ที่เป็นของแต่ละแบบ (น้ำหนัก ฯลฯ) อยู่ที่ variant

### 3.3 `inventory_items` — หน่วยขาย และ ชิ้น

```
id                int PK
inventory_id      int unsigned NOT NULL  -- variant
barcode           varchar(150) NULL UNIQUE   -- แถวหน่วยขาย
serial_no         varchar(150) NULL UNIQUE   -- แถวชิ้น
unit              varchar(50)            -- ชื่อหน่วยขาย (ฟอง โหล แผง) — แถวชิ้นใช้หน่วยฐาน
cut_stock         decimal(16,4) NOT NULL DEFAULT 1   -- หน่วยฐานต่อการยิง 1 ครั้ง
price             decimal(14,4) NULL     -- ราคาของหน่วยขายนี้ · NULL = variant.price × cut_stock
stock*            decimal(16,4) NOT NULL DEFAULT 0   -- เฉพาะแถวชิ้น: 1 อยู่ในคลัง · 0 ไม่อยู่
is_active         tinyint NOT NULL DEFAULT 1   -- เลิกใช้บาร์โค้ดนี้แล้ว (แทน instock เดิม)
KEY inventory_id
```

ข้อบังคับ (ตรวจใน model):

| ชนิดแถว | barcode | serial_no | cut_stock | มีได้เมื่อ |
|---|---|---|---|---|
| หน่วยขาย | ต้องมี | NULL | > 0 | ทุกวิธีนับ (นับรายชิ้นต้องเป็น 1) |
| ชิ้น | NULL | ต้องมี | = 1 | เฉพาะ `count_stock = 2` |

- แถวที่ถูกอ้างในเอกสารหรือสมุดบัญชีแล้วห้ามลบ ห้ามเปลี่ยนรหัส/ตัวคูณ — ปิดด้วย `is_active = 0`
  (บรรทัดเอกสารเก่าต้องอ่านความหมายเดิมของมันได้เสมอ)
- เปลี่ยนตัวคูณ = สร้างแถวใหม่ (ลังเปลี่ยนจาก 12 เป็น 24 คือบรรจุภัณฑ์ใหม่)

### 3.4 `inventory_cost_layer` — ล็อตที่รับเข้า

คงโครงเดิม เพิ่ม:

```
lot_no            varchar(50) NULL
expiry_date       date NULL
warehouse_id      int NOT NULL              -- ข้อ 3.7
KEY (inventory_id, inventory_item_id, warehouse_id, expiry_date)   -- สำหรับ FEFO
```

- รับเข้า 1 บรรทัด = 1 ชั้น · นับรายชิ้น = 1 ชั้นต่อชิ้น (ต้นทุนรายเครื่อง)
- `remaining_qty*` = `received_qty − Σ allocation.quantity` (รวมการคืน) · ชั้นของใบรับที่ถูกกลับรายการแล้ว = 0
  (การถอนชั้นไม่เขียน allocation — `Fifo::withdraw`)

### 3.5 movement · stock · allocation

คงโครงเดิม + `warehouse_id` (ข้อ 3.7) ความหมายที่ล็อกไว้:

- `inventory_item_id` = **ระดับที่ลงบัญชี** : นับจำนวน = 0 · นับรายชิ้น = แถวชิ้น
- `quantity` = **หน่วยฐานเสมอ**
- `sku` บนแถวสมุดบัญชี / ชั้นต้นทุน / allocation = **รหัสที่ใช้จริง** (ข้อมูลดิบ) : serial ของชิ้น ·
  บาร์โค้ดของหน่วยขาย · ไม่ระบุหน่วย = sku ของ variant — ยอดลงระดับ variant ก็ยังตรวจย้อนได้ว่าขายเป็นลังหรือเป็นชิ้น
- `sku` บนแถวยอดคงเหลือระดับ variant (`inventory_item_id = 0`) = sku ของ variant
- หน่วยขายที่ยิงจริงหาได้อีกทางจาก `reference_item_id` → บรรทัดเอกสาร

### 3.6 `order_items` — บรรทัดเอกสาร (ข้อมูลดิบของการซื้อขาย)

```
inventory_id      variant
inventory_item_id แถวที่ยิงจริง (หน่วยขาย หรือ ชิ้น)
sku               sku ของ variant ณ วันออกเอกสาร      (แทน product_code)
code              รหัสที่ยิงจริง — barcode หรือ serial  (แทน product_no)
lot_no            ล็อตที่ระบุ (ถ้ามี) — ขาเข้า = ล็อตที่รับ · ขาออก = ตัดจากล็อตนี้
expiry_date       วันหมดอายุของล็อตที่รับเข้า (ใบรับ) — บรรทัดคือข้อมูลดิบ บันทึกซ้ำแล้วชั้นใหม่ได้ค่าเดิม
topic, unit       ชื่อและหน่วยขาย ณ วันออกเอกสาร
quantity          จำนวน "หน่วยขาย"
unit_factor       ตัวคูณ ณ วันออกเอกสาร                 (ใหม่)
base_qty          = quantity × unit_factor (หน่วยฐานที่ตัด) (แทน cut_stock ที่ชื่อชนกัน)
price, discount, vat, total
cost_price*       ต้นทุนรวมของบรรทัด = Σ allocation ของบรรทัดนี้
```

`cut_stock` เหลือความหมายเดียวคือ **ตัวคูณของหน่วยขาย** (`inventory_items`) · ธงของ `inventory_template`
คือ `stock_in` / `stock_out` · `reserve_stock` = จองของ (นับเป็นขาออกเมื่อต้องระบุเครื่อง)

`Document\Model::save()` เป็นจุดเดียวที่เติมบรรทัดจากทะเบียน (ฟอร์ม · ตะกร้า · การแปลงเอกสาร ส่งมาแค่แถวที่อ้างและจำนวน):

| ค่า | ที่มา |
|---|---|
| `sku` | ค่าที่บรรทัดมีอยู่ (ณ วันออกเอกสาร) · ว่าง = sku ปัจจุบันของ variant |
| `code` · `unit_factor` | อ้างแถวหน่วยขาย/ชิ้น = จากทะเบียน (เปลี่ยนไม่ได้เมื่อถูกอ้างแล้ว) · ไม่อ้าง = ค่าที่ส่งมา / sku · ×1 |
| `base_qty` | `quantity × unit_factor` เสมอ |
| `cost_price` | ไม่รับค่าที่ส่งมา — ลงบัญชีแล้วเขียนจากสมุดบัญชี (`Posting::movementCost`) · ร่าง/ยกเลิก/ไม่นับสต๊อก = NULL |
| ทุนขาเข้าต่อหน่วยฐาน | `total ÷ base_qty` (หลังส่วนลดของบรรทัด · ราคาตามที่กรอก) |

นับรายชิ้น (เมื่อเอกสารแตะสต๊อกหรือจองของ และไม่ใช่ร่าง): บรรทัด n เครื่อง → n บรรทัดบรรทัดละเครื่อง ·
เครื่องที่ระบุใช้เครื่องนั้น · ที่เหลือ ขาเข้า = `Items::addSerial` · ขาออก = `Fifo::nextPiece` (ไม่ซ้ำเครื่องที่บรรทัดอื่นใช้) ·
ยอดเงินแบ่งเท่ากัน เศษไปบรรทัดสุดท้าย · จำนวนต้องเป็นจำนวนเต็ม · เครื่องเดียวกันสองบรรทัด = ปฏิเสธ ·
ทำหลังถอนผลเดิมของใบ จึงบันทึกซ้ำได้เครื่องเดิม · ใบที่ไม่แตะสต๊อก (ใบเสนอราคา) และร่าง คงบรรทัดตามที่ยิง

### 3.7 `inventory_warehouse` — คลัง (โครงเดียวกับ oms.in.th)

- ตัวติดตั้งสร้างคลังตั้งต้นให้ 1 แถว (`is_default = 1`) · ทุกแถวของยอด/สมุดบัญชี/ชั้นต้นทุน/allocation
  เก็บ id คลังจริงเสมอ — ผู้เรียกส่ง 0 หรือไม่ส่ง = คลังตั้งต้น (`Warehouse::resolve()` แบบ oms.in.th)
- `inventory_stock` UNIQUE (inventory_id, inventory_item_id, warehouse_id)
- oas ใช้คลังเดียว ไม่มีหน้าจัดการหลายคลัง · oms.in.th มีหน้าจัดการและการโอนระหว่างคลัง

## 4. ยิงบาร์โค้ด (POS / เอกสาร / ร้านออนไลน์)

ลำดับค้นหา — เจอที่ไหนหยุดที่นั่น:

1. `serial_no` ตรงตัว → ชิ้นนั้น (ถ้า `stock = 0` ฟ้อง "ขายไปแล้ว")
2. `barcode` ตรงตัว → หน่วยขายนั้น
   - variant นับรายชิ้น → เลือกเครื่อง หรือให้ระบบเลือกเครื่องตามวิธีตัด แล้ว **บันทึกเครื่องที่เลือก** ลงบรรทัด ·
     เอกสารรับเข้า (ฟอร์มส่ง `document_type` ไปกับการค้นหา) ไม่เลือก — บรรทัดคงเป็นหน่วยขาย แล้วเอกสารออกเลขเครื่องตอนบันทึก
3. `sku` ตรงตัว → variant · ใช้หน่วยขายที่ `cut_stock = 1` (ไม่มี = หน่วยฐานด้วยราคา variant)
4. `product_code` ตรงตัว → สินค้า · มี variant เดียวใช้ตัวนั้น หลายตัวต้องเลือก

ราคา = `items.price` ถ้ามี ไม่งั้น `variant.price × cut_stock`
จำนวนที่ตัด = `quantity × cut_stock` หน่วยฐาน · นับรายชิ้น 1 บรรทัด = 1 เครื่อง (ขาย 3 เครื่อง = 3 บรรทัด)

## 5. สต๊อกและต้นทุน

### 5.1 วิธีตัดของระบบ

ค่ากำหนด `stock_method` = `fifo` (ตอนนี้) — เตรียม `fefo` ไว้

| วิธี | เรียงชั้นที่จะตัด |
|---|---|
| fifo | `received_at`, `id` |
| fefo | `expiry_date` (ว่างไว้ท้าย), `received_at`, `id` |

### 5.2 รับเข้า

- นับจำนวน: 1 บรรทัด → 1 movement ที่ระดับ 0 → 1 ชั้น (พร้อม lot_no / expiry_date ถ้ากรอก)
- นับรายชิ้น: 1 เครื่อง → 1 แถวชิ้น + 1 movement + 1 ชั้น
  ไม่กรอก serial → ระบบออกเลข `{sku}-{เลขรัน 4 หลัก}` (`Items\Model::addSerial`) พิมพ์ฉลากได้
- lot_no ตัดช่องว่างหัวท้าย ว่าง = NULL · ยาวไม่เกิน 50 · expiry_date ต้องเป็นวันที่จริง `Y-m-d`

**ทุนการซื้อ (ใบรับซื้อ · movement `purchase`) ตามมาตรฐานการบัญชีเรื่องสินค้าคงเหลือ (TAS 2 / IAS 2)** —
`Document\Model::purchaseCosts()` · ทุนต่อหน่วยฐาน = ทุนของบรรทัด ÷ base_qty

| ขั้น | กติกา |
|---|---|
| 1. ส่วนลด | ยอดบรรทัด (หลังส่วนลดของบรรทัด) หักส่วนลดท้ายบิลที่เฉลี่ยตามสัดส่วนยอด — ทุกบรรทัดของใบรับเดียวกัน รวมบรรทัดที่ไม่นับสต๊อก (ส่วนลดของบิลจึงไม่ไปกองที่สินค้าเกินส่วน) |
| 2. ภาษีซื้อ | ยอดภาษีที่บันทึกบนใบ เฉลี่ยลงบรรทัดที่คิด VAT ตามฐานภาษีหลังส่วนลด (ไม่คำนวณจากอัตราใหม่ — ทุนรวมตรงกับเอกสาร) · ราคารวมภาษี = ถอดออกจากยอดบรรทัด · ราคาแยกภาษี = ภาษีบวกเพิ่ม |
| 3. ค่าตั้ง `input_vat_creditable` | 1 (ค่าเริ่มต้น) กิจการเครดิตภาษีซื้อได้ = ทุนไม่รวมภาษีซื้อ · 0 = ภาษีซื้อเป็นส่วนหนึ่งของทุน · ใช้กับใบที่บันทึกหลังเปลี่ยน |
| 4. ค่าใช้จ่ายในการซื้อ | `orders.shipping_cost` ของใบรับ (ค่าขนส่งเข้า อากร — ช่องมีเฉพาะใบฝั่งซื้อ) เฉลี่ยลงบรรทัดสินค้าที่นับสต๊อกตามมูลค่าหลังส่วนลดก่อนภาษี · บรรทัดบริการไม่รับ · ไม่อยู่ในฐานภาษี (สัญญาเดียวกับ `Cart::totals`) |

ภาษีหัก ณ ที่จ่ายไม่กระทบทุน (เป็นเรื่องการจ่ายเงิน) · ใบเข้าอื่นที่ไม่ใช่ซื้อหรือคืน (ยืมคืน) ยังใช้ยอดบรรทัด ÷ base_qty

**เศษของทุน** — ทุนต่อหน่วยเก็บ 4 ตำแหน่ง · การตัดที่ทำให้ชั้นหมดใช้ "ทุนที่รับเข้าทั้งชั้น − ทุนที่ตัดไปแล้ว" (`Fifo::closingCost`)
ทุนขายรวมของชั้นจึงเท่าทุนซื้อพอดี (200 ÷ 60 ขายหมด = 200 ไม่ใช่ 199.998) · ใช้เฉพาะส่วนต่างระดับเศษ
(≤ 0.0001 ต่อหน่วยที่รับ + 0.01) · การกลับรายการหักล้างด้วย total_cost เดิมตรงตัว

### 5.3 ตัดออก

- ระบุชิ้น/ล็อต → ตัดชั้นของชิ้น/ล็อตนั้น · ล็อตที่ไม่เคยรับเข้าคลังนั้น = รหัสผิด ปฏิเสธ ·
  ล็อตเหลือไม่พอ ปฏิเสธ (เว้นสินค้ายอมติดลบ — ส่วนที่ขาดไม่มีต้นทุน)
- ไม่ระบุ → ตามวิธีตัด (ข้อ 5.1)
- เขียน allocation ทุกชั้นที่ถูกตัด · ต้นทุนบรรทัด = ผลรวม allocation

นับรายชิ้น — สมุดบัญชีรับเฉพาะ **แถวชิ้นของ variant นั้น ทีละ 1 เครื่อง** (`Posting::assertPiece`):

| กรณี | ผล |
|---|---|
| ไม่ระบุหน่วย หรือส่งแถวหน่วยขาย (บาร์โค้ดรุ่น) | ปฏิเสธ "ต้องระบุหมายเลขเครื่อง" |
| จำนวน ≠ 1 | ปฏิเสธ "ทีละหนึ่งเครื่อง" |
| รับเข้าเครื่องที่มียอดอยู่แล้ว (คลังไหนก็ตาม) | ปฏิเสธ "อยู่ในคลังแล้ว" |
| ตัดเครื่องที่ไม่อยู่ในคลังนั้น | ปฏิเสธ "ไม่อยู่ในคลัง" — ยอมติดลบไม่ใช้กับรายชิ้น |

การ **เลือกเครื่อง** (`Fifo::nextPiece` — ตามวิธีตัด เฉพาะเครื่องในคลังที่ไม่ถูกจอง) และการ **ออกเลขเครื่อง**
(`Items::addSerial`) ทำที่บรรทัดเอกสารแล้วบันทึกลงบรรทัด ไม่ใช่ในสมุดบัญชี — บันทึกเอกสารซ้ำต้องได้เครื่องเดิม

ทุกรายการที่อ้าง `inventory_item_id` ต้องเป็นแถวของ variant นั้น (อ้างข้ามสินค้า = ปฏิเสธ)

### 5.4 คืน

ยกเลิกเอกสาร → กลับเข้าชั้นเดิมผ่าน `source_allocation_id` — นับรายชิ้นได้เครื่องเดิมกลับมา `stock = 1`

เอกสารคืน (ผู้ใช้ตัดสิน 2026-10-23) :

| ชนิด | ฝั่ง · ทิศ | ทุน (TAS 2) |
|---|---|---|
| RET ใบคืนสินค้าจากลูกค้า | ขาย · รับเข้า `return_in` | ทุนเดิม (`Document::returnCosts`) : เครื่อง = ทุนของการขายเครื่องนั้นครั้งล่าสุด · บรรทัดที่แปลงจากบรรทัดขาย = ทุนต่อหน่วยฐานของบรรทัดขาย · ไม่รู้ที่มา = ทุนต่อหน่วยของการขายครั้งล่าสุดก่อนวันที่คืน · ไม่เคยขาย = ทุนถัดไป · **ไม่ใช่ราคาบนใบคืน** |
| RTS ใบคืนสินค้าไปยังผู้ขาย (oms.in.th เท่านั้น) | ซื้อ · ตัดออก `return_out` | บรรทัดที่แปลงจากบรรทัดใบรับ = ของออกจากชั้นของใบรับนั้น (`from_movement_id`) ด้วยทุนของมัน — เหลือไม่พอ = ปฏิเสธ · ไม่อ้างใบรับ = ตามวิธีตัด (ระบุล็อต/เครื่องได้) |

สายของบรรทัด : `order_items.source_item_id` / `root_item_id` — `Document::convert()` และการแปลงจากฟอร์มผูกให้ ·
บันทึกซ้ำคงสายเดิม (`write()` อ่านสายของบรรทัดเดิมจาก id ที่ฟอร์มส่งกลับ)

ยอดขาย (หน้าแรก : ยอดขาย · สินค้าขายดี — `Base::revenueStatuses()`) : รับรู้เมื่อส่งมอบสินค้า (TFRS 15) = ใบฝั่งขายที่ตัดสต๊อก (ใบเสร็จ)
หักใบฝั่งขายที่รับของคืน (RET) · เฉพาะใบที่ออกแล้ว (ร่าง/ยกเลิกไม่นับ) · ใบเสนอราคา ใบสั่งขาย ใบแจ้งหนี้ ในสายเดียวกันไม่นับ ยอดจึงไม่ซ้ำ
oms.in.th (ผู้ใช้ตัดสิน 2026-10-24) : ยอดขายหน้าแรก = **ใบเสร็จรับเงินเท่านั้น** (ใบฝั่งขายที่ชำระหนี้ — ธง `settles` ของโมดูลบัญชี
ที่ `modules/accounting/install/upgrade.php` ตั้งให้ OUT) ไม่หักใบคืน · ใบส่งของ (DN) ที่ตัดสต๊อกไม่นับ — แกนตัดสินจากธงนี้:
มีใบฝั่งขายที่ชำระหนี้ = ใช้ใบเสร็จ · ไม่มีคอลัมน์ (oas ไม่มีโมดูลบัญชี) = ใช้กติกาส่งมอบด้านบน

### 5.6 cache และคำสั่งคำนวณใหม่

| cache | สูตร (จากข้อมูลดิบ) |
|---|---|
| `inventory_stock.qty` | Σ movement (in − out) ต่อ variant × ระดับ × คลัง |
| `inventory_stock.reserved_qty` | Σ base_qty ของเอกสารจองที่ยังเปิด |
| `inventory_cost_layer.remaining_qty` | received_qty − Σ allocation (สุทธิการคืน) · ใบรับที่ถูกกลับรายการ = 0 |
| `inventory.stock` | Σ `inventory_stock.qty` ของ variant |
| `inventory.cost` | unit_cost ของชั้นแรกตามวิธีตัดที่ยังเหลือ · ไม่มีของเหลือ = ชั้นที่รับล่าสุดที่ไม่ถูกยกเลิก · ไม่เคยรับเลย = คงค่าที่ผู้ใช้กรอก (`Fifo::nextCost`) |
| `inventory_items.stock` | แถวชิ้น = Σ `inventory_stock.qty` ของเครื่องนั้นทุกคลัง · แถวหน่วยขาย = 0 |
| `inventory_stock.sku` | ระดับ 0 = sku ของ variant · แถวชิ้น = serial_no |
| `inventory.topic` | product.topic + ค่าตัวเลือก |
| `order_items.cost_price` | Σ allocation ของบรรทัด (ขั้น 3) |

คำสั่ง `Inventory\Posting\Model::rebuild($inventoryId = 0)` (0 = ทุก variant · ใน transaction เดียว) เขียน cache
ทั้งหมดใหม่จากข้อมูลดิบ แล้วคืนรายการแถวที่ cache เดิมไม่ตรง `[[table, key, field, sku, cached, actual], ...]`
(ใช้ตรวจหาบั๊ก — ว่าง = ทุกทางเขียนผ่าน Posting ถูกต้อง) · ชั้นของใบรับที่ยกเลิกแล้วแต่ยังมี allocation ค้าง
ซ่อมเองไม่ได้ รายงานเป็น `inventory_cost_allocation` พร้อม `note` · ชุดทดสอบเรียกหลังกลุ่มที่เดินสต๊อก และท้ายชุดต้องได้ `[]`

## 7. ความเข้ากันได้กับ oms.in.th

oas = รุ่นแจกฟรี หลังบ้านของร้านออนไลน์/POS ขั้นพื้นฐาน มีเฉพาะฟีเจอร์ที่จำเป็น
oms.in.th = รุ่นเต็ม (หลายคลัง ใบปรับยอด ecommerce pos ฯลฯ) — ลูกค้าย้ายจาก oas ไป oms ได้

กติกา:

1. **สคีมาของ oas เป็นสับเซตของ oms.in.th** — ชื่อตาราง ชื่อคอลัมน์ ชนิด และความหมายเหมือนกันทุกตัว
   ย้ายข้อมูล oas → oms คือ INSERT … SELECT ตรง ๆ ไม่มีการแปลงค่า
   (ตารางที่มีแค่ oms ว่างเปล่าได้ คอลัมน์ที่มีแค่ oms มีค่าตั้งต้นเสมอ)
2. **oms.in.th เป็นต้นทาง · oas เป็นรุ่นตัดฟีเจอร์ที่ใช้ "แกน" เดียวกัน**
   - แกน = สคีมาและ model ของสินค้า/สต๊อก/ต้นทุน/เอกสาร (product · variant · items · warehouse ·
     posting · fifo · stocks · document) — โค้ดเหมือนกันทุกบรรทัดในสองที่
   - ฟีเจอร์ที่ oas **ตัดโค้ดออกจริง** (ไม่ใช่ซ่อน): หน้าจัดการหลายคลัง/โอนคลัง · ใบปรับยอด ·
     ที่อยู่ลูกค้าหลายที่ (`customer_address`) · พิมพ์ซองจดหมาย · PDF ·
     ใบสั่งขาย SO (จองของ) · ใบคืนสินค้าไปยังผู้ขาย RTS (2026-10-24 — engine การจอง/`from_movement_id` ยังอยู่ในแกน)
     (model คลังเป็นแกน เหมือนกันทั้งสองที่ — oas แค่ไม่มีหน้าจัดการ จึงมีคลังตั้งต้นคลังเดียว)
   - ขั้น 0 = ยกแกนของ oms (คลัง · DECIMAL · กันแก้ใบรับเข้าที่ถูกตัดไปแล้ว) มาที่ oas โดยไม่เอาฟีเจอร์ที่ตัด
     หน้าจอ (controller/template) ยังไม่ซิงก์ เพราะขั้น 4 จะทำหน้าสินค้าใหม่ทั้งหมดตามแบบนี้อยู่แล้ว
   - ทำแบบใหม่บนแกนที่ oas (ทดสอบเร็ว) แล้วคัดลอกแกนกลับ oms
3. ฟีเจอร์ที่ oas ไม่ทำ ต้องไม่ทิ้งข้อมูลที่ขัดกับ oms — เช่น oas ไม่มีหน้าจัดการคลัง แต่ยังเก็บ id คลังตั้งต้นจริง
4. **ข้อยกเว้นที่ต้องแปลงตอนย้าย oas → oms:** ที่อยู่ลูกค้า — oas เก็บในตาราง `customer`
   oms เก็บใน `customer_address` (ตัวย้ายข้อมูลต้องสร้างแถวที่อยู่ตั้งต้นจากคอลัมน์ของ customer)
5. **ขอบเขตของ "แกน"** = engine + ทะเบียนสินค้า: `base` · `warehouse` · `posting` · `fifo` · `stocks` ·
   `ledger` · product/variant/items model · ตารางของสิ่งเหล่านี้ — โค้ดเหมือนกันทุกบรรทัด
   เอกสาร (`document.php`) ไม่อยู่ในแกน (oms มีที่อยู่ จัดส่ง ธงบัญชีเพิ่ม) แต่เรียก engine ผ่าน API เดียวกัน
   (`Posting::post/reverse` · `Fifo::begin/finish`)

ข้อจำกัดจาก `oms.in.th/PLAN_UNIFIED_EDITIONS.md` (D7 แก้เป็นแกนเดียวกัน 2026-10-23):

- oms มีผู้เช่าจริง 1 ราย (ใช้ OUT/INV) — ตอนยกแบบนี้ไป oms ต้องย้ายข้อมูลสินค้าจริงผ่าน `install/schema.php`
